## Orchestrator finding: smoke `stale_revision`

**Fixed in `records::integrations::deliver`.** Accepting a records delivery previously called `records::common::changed`, which unconditionally called `cases::core::bump_revision`. The asynchronous receipt for an earlier payment could therefore invalidate the revision read immediately before Priya submitted or issued a decision. Delivery acceptance now appends the history event and audit entry directly, without changing the case command revision. Domain transitions continue to use optimistic concurrency.

Regression: `records::tests::integration_delivery_receipt_does_not_invalidate_staff_revision` delivers through the real mock receiver, verifies the receipt history remains, and successfully executes a command using the revision read before delivery. The pre-fix implementation changes that revision from 1 to 2 and fails the test. `scripts/smoke-integration.sh` was not modified and has no new retries.
